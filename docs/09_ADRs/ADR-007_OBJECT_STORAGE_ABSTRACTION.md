# ADR-007 — Object Storage Abstraction

**Project:** ForgeCRM

**Status:** Accepted

**Date:** 2026-07-25

**Decision Makers:** ForgeCRM Engineering

---

# Context

ForgeCRM stores user-uploaded files, including:

- Documents
- Attachments
- Images
- Company logos
- Exported reports
- Generated PDFs

The application should support local development, testing, and production deployments without requiring changes to business logic.

Direct dependence on a specific object storage provider would increase vendor lock-in and complicate future migrations.

---

# Decision

ForgeCRM will implement a **Storage Abstraction Layer**.

Business modules interact only with a storage interface.

Concrete implementations provide support for:

- MinIO (development and testing)
- Amazon S3 (production)

Storage providers are selected through configuration rather than application code.

---

# Rationale

A storage abstraction provides:

- Reduced vendor lock-in
- Easier testing
- Cleaner architecture
- Environment flexibility
- Future extensibility
- Consistent developer experience

Business logic remains independent of storage implementation details.

---

# Storage Responsibilities

The storage layer is responsible for:

- Uploading files
- Downloading files
- Deleting files
- Generating signed URLs
- Managing object metadata
- Reporting storage errors

Business modules remain responsible for authorization and business rules.

---

# Alternatives Considered

## Direct Amazon S3 Integration

Advantages:

- Simple implementation
- Full access to S3 features
- Mature SDK

Disadvantages:

- Vendor lock-in
- Difficult local development
- Harder testing
- Business logic coupled to AWS

Rejected because it tightly couples application code to a single provider.

---

## Local Filesystem Storage

Advantages:

- Very simple
- Easy development
- No external service required

Disadvantages:

- Poor scalability
- Difficult backups
- Limited availability
- Unsuitable for production SaaS deployments

Rejected because it does not meet production requirements.

---

## Database BLOB Storage

Advantages:

- Single backup process
- Strong transactional consistency

Disadvantages:

- Large database growth
- Poor storage efficiency
- Increased backup times
- Reduced database performance

Rejected because binary assets should remain outside the transactional database.

---

# Consequences

Positive:

- Provider independence
- Easier testing
- Flexible deployments
- Cleaner architecture
- Simplified local development
- Easier future migration

Negative:

- Additional abstraction layer
- Provider-specific features may require explicit extensions
- Slight increase in implementation complexity

These trade-offs are acceptable for ForgeCRM.

---

# Implementation Guidelines

- Business modules use only the storage interface.
- Object keys should be generated by the application.
- Storage providers should not expose provider-specific APIs to business modules.
- Metadata should be stored separately in PostgreSQL.
- Uploaded files should be validated before storage.
- Download authorization should occur before signed URL generation.
- Storage configuration should be environment-specific.

---

# Security Considerations

Object storage should enforce:

- Private buckets by default
- Signed URLs for temporary access
- Server-side encryption where supported
- File size limits
- MIME type validation
- Malware scanning workflow
- Least-privilege credentials

Storage access should be fully auditable.

---

# Future Evolution

Future enhancements may include:

- Azure Blob Storage
- Google Cloud Storage
- Multi-region replication
- Lifecycle policies
- Intelligent storage tiering
- Content Delivery Network (CDN) integration

New providers should implement the existing storage interface rather than modifying business modules.

# Review

This decision should be reviewed if:

- Business requirements demand provider-specific storage capabilities.
- Multi-cloud deployments become a strategic requirement.
- Object storage performance or cost becomes a significant operational concern.
- A future storage technology provides compelling, measurable advantages with acceptable migration effort.
